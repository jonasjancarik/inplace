Why not just use a rich-text editor?

Agents now write documents as hand-crafted HTML, with real typography, colour-coded tables, charts and print layouts. Rich-text editors turn that into their own format and lose half of it. inplace leaves the file alone and only lets you change what you can see.

One

The HTML file is the document

There's no editor format, database or export step. What you see in the browser is the file on disk, and what you print or send is that same file.

Two

Your edits touch one element

Typing changes the text inside a single paragraph, heading, list item or table cell. Adding or moving something touches only that element's markup. CSS, SVG charts and everything else stay byte-for-byte the same.

Three

Comments point at the right place

Every block and table gets a stable data-id. When you comment on an element in your agent's browser, the agent gets that id and finds the exact spot in the file, even after the wording has changed.

Four

The agent sees what you changed

inplace reports every edit you make. The agent reads that before it acts, so a changed amount gets its total fixed and a moved section gets its references updated, without you having to ask.

Five

Formatting stays plain HTML

Bold, italics, code and links are written as <strong>, <em>, <code> and <a>, so the document's own styles decide how they look.

Six

You can both work at once

Edits to different blocks never get in each other's way. If the agent rewrites the paragraph you're typing in, your save is refused instead of overwriting its text, and what you typed goes to your clipboard.

What you can do on the page

Everything here is saved straight to the file after a short pause. Anything bigger, like a new section, a chart or a different layout, you ask for with a comment.

Get started

You need Node.js 22 or newer and an agent with a built-in browser, such as Claude Code in the Claude app or Codex.

  1. Give your agent the skill

    It teaches the agent to start inplace, find commented elements by their id, keep the ids intact, and check totals and charts after you change a number.

    npx skills add jonasjancarik/inplace

  2. Open your document

    Ask the agent to open it in inplace, or start it yourself and open localhost:8765 in the agent's browser.

    npx github:jonasjancarik/inplace path/to/document.html

  3. Edit, or leave a comment

    Type, add paragraphs and rows, format and drag things around on the page; changes save after a short pause. For new sections, layout or charts, comment on the element and let the agent do it.

What happens to your file

The first time the page opens, inplace adds a data-id to each block and container that doesn't have one. The ids don't change how the page looks or prints, and existing ids are never renamed.

After that, the file only changes when you make a change on the page, and then only in the block you edited or the element you moved. If the document is in git, every edit shows up as a small, readable diff.

How the agent finds out about your edits

While it runs, inplace prints one line for every change made on the page, showing only the part that changed. The skill has the agent start inplace in the background and read these lines before it handles a comment or touches the file.

That way it notices a changed amount and fixes the totals and charts that depend on it, or a moved section and the “see the table below” that now points the wrong way. You can also just tell it to check your edits.

Good to know

Small changes on the page, the rest through the agent

You can type, format, add and remove paragraphs, list items and rows, and reorder things among their neighbours. New sections or tables, moving something into another section, styling and charts are asked for with a comment.

The page doesn't do the maths

When you change an amount, the agent sees it and updates totals and charts, as long as it has the skill. Mark values that shouldn't change by hand with data-locked.

Made for your own computer

It serves one document with no login. Keep it on a network you trust, or start it with --host 127.0.0.1.
